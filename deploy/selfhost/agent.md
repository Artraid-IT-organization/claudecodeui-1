# deploy/selfhost — установка на чужой сервер и самообновление

Кому: тому, кто правит `install.sh` / `update.sh` или инструкции `README.md`, `INSTALL-FOR-AI.md`
в корне. Заведено 15.09.26: человек отправляет ссылку своему Claude — тот ставит интерфейс сам.

## Цепочка
- Выкатка у Егора (`claudecodeui-shared`, HEAD) → `~/scripts/ccui-publish-main.sh` (крон :35, вне репо)
  вливает её в `origin/main` → ночью у чужих `update.sh` берёт `main`.
- `main` — единственная точка, откуда обновляются чужие копии. Не форсить; всё, что туда
  попадает, через час у всех. Репо публичное — секрет в коде уйдёт наружу.

## Неочевидное
- `npm ci --include=dev` обязательно: при `NODE_ENV=production` (так у пользователя claude
  на сервере Егора) npm молча пропускает vite/tsc/husky, `prepare` падает «husky: not found».
- Тесты сервера: 11 из 364 падают от окружения в любой версии (учётные данные, навыки, shell).
  Мерка — `.test-fails` работающей версии, новая не должна падать чаще.
- Проба запускает сервер с временным `HOME` и пустой базой — иначе трогает настоящие чаты.
- Владелец (id 1) создаётся через `/api/auth/register`: на `OPEN_REGISTRATION` он разрешён
  только пока пользователей нет. Ссылку входа выпускает `regenerate-login-link`
  (у созданного паролем `login_token` пуст).
- `~/.claude-webuser-1` — ссылка на `~/.claude`, не копия: копии `.credentials.json`
  теряют вход при продлении ключа.
- `KillMode=process`: перезапуск не обрывает работающие чаты. До 6 утра обновление ждёт,
  пока в cgroup службы один процесс.
- sslip.io делит недельный лимит Let's Encrypt на всех — запасной nip.io, дальше только свой домен.
- Голос у чужих — ключ Groq напрямую (`VOICE_API_BASE_URL=https://api.groq.com/openai/v1`,
  модуль шлёт на `/audio/transcriptions`). `AUDIO_ARCHIVE_*` не задаём — архив и отправка
  в Telegram остаются выключены.

## Проверка правок
Без root: `~/.cache/ccui-selfhost-test.sh` на сервере Егора (клон ветки → `update.sh --first`
→ владелец, ссылка, вход, 403 постороннему). Части с nginx/certbot/systemd здесь не проверить —
только чтением и на чистом сервере.
